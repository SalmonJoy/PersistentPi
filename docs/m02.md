# M0.2: one real local Runner

## Scope and provenance

M0.1 is frozen by annotated tag `m0.1` at `f189aae488fdcb3eab04849aa0d6505d38376aff`.
It was clean and passed all 62 original tests plus its six-trial matrix before
changes. Those tests remain unchanged. Protocol 0.1 and its scripted fixtures
remain supported. Protocol 0.2 names the extensions below instead of silently
changing simulated accounting or allowing unreviewed Python execution.

No Planner, memory retrieval, reflection, generated tools, scaffold evolution,
promotion, cloud inference, Pi access or model downloads are part of M0.2.
Codex implements the harness but never repairs candidates inside an experiment.

## Boundaries

`ExperimentManager -> Runner -> OllamaModel -> strict ActionRequest -> Supervisor`
uses the existing read/exact-edit/public-test tools. The public verifier and hidden
evaluator still score content-addressed checkpoints. A verification submission is
an attempt; reading/editing/finishing are decisions, not attempts. Stop on first
public pass. Hidden evaluation runs only after normal termination and never returns
to the Runner. Unsubmitted edits are not selected: the last submitted checkpoint,
or initial checkpoint if none, is scored. More attempt allowance need not mean
more attempts actually occur when another limit or failure terminates the run.

The adapter only constructs context, calls local HTTP, parses JSON and returns
telemetry. It does not inspect repositories, select strategies, patch code, repair
responses or consult a second model. Unknown tool names remain intact for the
Supervisor to reject. Tools/logger/evaluator/supervisor remain trusted code.

### Generated-code execution profile

The old verifier executes reviewed Python fixtures, which cannot safely be used
for unrestricted model output. New tasks declare `bounded-python-1`: a small
data-only AST interpreter. Generated source is parsed, never compiled, evaluated,
executed or imported as Python. Trusted tests call wrappers backed by that
interpreter. Edits are checked before being written; public/private execution
uses the same profile. No additional model tool is introduced.

Supported: top-level pure functions, primitive values, arithmetic/comparisons,
conditionals, local assignments, bounded `for` loops, slices, one-generator list
comprehensions, same-module function calls, and the builtin/string method list
shown verbatim in the prompt. No imports, reflection, arbitrary attributes,
classes, I/O, decorators, exception handling, `while`, keyword arguments, mutable
list methods, or full Python semantics. Source/AST, integer/string/container size,
recursion, traversal and instruction fuel are bounded. Existing test subprocess
timeout and process-tree cleanup also apply.

This is a deliberately constrained language and a new evaluation profile, not a
general Python benchmark or proven OS sandbox. Unsupported correct Python can be
rejected; count it as an execution-profile limitation, not evidence of general
coding incapability. Trusted test authors and the local runtime remain trusted.
Hard host RAM/disk isolation and arbitrary-code execution remain deferred.

## Model and configuration

TOML configuration is authored, validated and resolved into an immutable manifest.
The model tag is configurable; the adapter does not depend on a particular family.
Record installed digest, quantization, parameter count, API runtime version,
template/system hashes when exposed, backend defaults and explicit settings.
Digest/runtime are checked again before every generation; mismatch interrupts
without inference. There is no pull/install or remote-model fallback path.

The installed `llama3.2:1b` is Q8_0 with 1,235,814,432 parameters; it is not the
preferred absent `qwen2.5-coder:0.5b`. All current runs are labeled non-baseline.
See [inventory](m02-runtime-inventory.md) for exact digest and laptop measurements.
The preset uses temperature 0, seed 42, `num_ctx=4096`, `num_predict=256`,
30-second request timeout and `keep_alive="5m"`. Backend defaults and hardware
may still affect reproducibility; a configured seed is not a determinism guarantee.

HTTP is stdlib `http.client`, loopback-only and non-streaming. Requests use
`format="json"`; this backend constraint is an explicit fixed experimental factor,
not a response repair. No proxies, redirects, cloud SDKs or automatic HTTP retries.
See Ollama's [chat API](https://docs.ollama.com/api/chat),
[model listing API](https://docs.ollama.com/api/tags) and
[parameter reference](https://docs.ollama.com/modelfile).

## Prompt and malformed output

`runner-json-1` requires exactly one JSON object with `tool` and `arguments`, using
the existing ActionRequest contract. No reasoning field or chain of thought.
Duplicate keys, non-finite numbers, prose/fences and extra fields are rejected.
Malformed output is retained, charged one decision and all reported tokens, then
terminates normally and scores the selected checkpoint. No format-repair call.
The only supported `repair` setting is false; future repair needs a separate factor.
Structurally valid but invalid tools/arguments/paths are charged as rejected tool
calls and provide ordinary rejection feedback. Invalid finish arguments likewise
consume a rejected call. Repetition is classified, not silently corrected.

`recent-public-1` includes task description, relative readable/editable paths,
tool contracts, remaining attempt/decision/tool/token budgets and at most four
recent public observations. It excludes timing/UUID/checkpoint fields, unknown
result fields, private evaluation and trusted host paths. Path-bearing feedback
lines are removed, fields truncated to 1800 UTF-8 bytes, and oldest observations
dropped until the canonical messages fit 7000 bytes. Metadata records truncation,
redaction, prompt hash and bytes. Task/tool context alone exceeding the bound is
an infrastructure error, never silently summarized. No memory or retrieval.

## Accounting, cancellation and failure taxonomy

Existing SQLite tables/migration are unchanged. Manifest and versioned event
payloads carry additions; full requests and raw model outputs are checksummed
artifacts in exports. Each model request receipt precedes the call. A completed
call records UTC start/end, monotonic latency, identity, status, nullable prompt/
completion/total token counts, backend load/prompt/generation/total nanoseconds,
cached prompt count when exposed and derived generation tokens/second.
Additional nonnegative count/duration metrics are retained. `usage_kind` is
`measured`, never mixed with protocol 0.1 `simulated` accounting.

The completion cap is bounded by remaining tokens, but actual prompt-token cost
is not known before inference. Record actual backend usage even if it exceeds the
budget; do not execute the resulting action after an overrun. Unknown counts stay
NULL, with separately reported known lower bounds. Timeout/transport failures or
missing counts interrupt without retry/evaluation, rather than pretending zero
usage or a benchmark failure. Backend work after a disconnected request may not
be measurable or cancellable; no quota-exhaustion experiments are performed.

STOP is checked at existing boundaries and after a call. A non-streaming call may
delay acknowledgement until its configured timeout; disconnect does not guarantee
backend cancellation. This is not an instantaneous inference-kill facility.

Taxonomy `0.2` uses deterministic events: malformed_model_output, invalid_action,
incorrect_edit (rejected edit), public_test_failure, hidden_test_failure (research
only after termination), timeout, repeated_action, budget_exhausted and
infrastructure_failure. Counts are overlapping event counts, not disjoint task
labels or proof of semantic causes. Full evidence remains available.

## Development smoke protocol

Eight new tiny tasks: rectangle area, index boundary, sign conditional, first-colon
parsing, discount/quantity interaction, stable uniqueness, underspecified public
parity cases, and longest balanced-parentheses substring. Last task is harder.
Each has separate fast deterministic public/private tests. Trusted reference
solutions are test-only and never model context. The original three scripted
fixtures remain regression tests, not the primary live score.

`scripts/smoke_m02.py` runs task-major budgets 1, 3 and 5 (24 trials), then three
replicates each of area and parsing at budget 3 (6 trials). Other limits stay fixed:
15 decisions/tools, 16000 tokens, 120 seconds, 5 seconds per verifier, bounded
workspace/edit/output sizes. These are development settings, not Pi defaults.
No model warm-up, adaptive prompting, per-task strategy changes or hidden-result
tuning. The same resident server/cache is used with keep-alive; cold-load cost,
run order and changing laptop contention can affect time comparisons. Record
load time separately; this suite is not a randomized performance study.

Reports contain counts, public/private outcomes, actual attempts, decisions,
valid/invalid outputs, tool calls, nullable tokens, request/inference/end-to-end
time, generation throughput and failure events. Budget deltas report recovered
and lost tasks plus total token/wall cost; reports reject unequal task cohorts or
changed model/scaffold/limit factors. Repeats compare initial prompt hashes,
complete output/prompt traces and outcomes. Divergent outputs under the same
initial input are an observation, not a general nondeterminism estimate. No
significance tests or general test-time-scaling claims are justified.

## Reproduction and artifacts

From this repository with the existing virtual environment and clean Git state:

```powershell
.\.venv\Scripts\python.exe scripts\validate.py
.\.venv\Scripts\python.exe scripts\smoke_m02.py
.\.venv\Scripts\python.exe scripts\persistentpi.py --state .local/m02/RUN-FOLDER status
.\.venv\Scripts\python.exe scripts\persistentpi.py --state .local/m02/RUN-FOLDER stop --run RUN-ID
```

Tests use fake HTTP responses, never require Ollama and never download models.
`validate.py` runs all tests plus the original matrix and audited export.
Live execution requires the installed Ollama server at 127.0.0.1:11434. If stopped,
start the installed `ollama serve` (set `OLLAMA_NO_CLOUD=1` in its environment).
Do not launch a duplicate listener. Missing model causes an explicit error.
Optional, only after separate download approval: `ollama pull qwen2.5-coder:0.5b`,
then run `scripts\smoke_m02.py --config configs/m02-qwen-development.toml` as a new
experiment. Do not relabel existing llama results as Qwen or a small-model baseline.

The live script prints its ignored `.local/m02/<UUID>/` state folder. It contains
`experiments.sqlite`, artifacts, workspaces, `summary.json`, `report.md` and
`research.zip`. Export contains all tables as JSON/CSV, manifests, authored config,
model requests/output, checkpoints and public/private research evidence, with
checksums. It is a researcher archive: never feed the full export to a Runner.
The database plus frozen Git commit and installed model digest reconstruct the
protocol and trace, not bitwise deterministic future inference. An independently
archived model/runtime would be needed if installed weights later disappear.
Interrupted calls remain auditable; automatic replay/resume is not implemented.

Stop at M0.2. No M0.3 work is included.
