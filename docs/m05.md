# M0.5 Raw Coding vs Action Selection

Preregistration: `configs/m05-preregistered.json`, commit `2e929c6`. M0.4 clean
`75c2b33` passed 133 tests and original validation matrix before annotated tag
`m0.4`. Prior records and tasks remain unchanged. This is a laptop-only diagnostic.

## Conditions

| Condition | Information | Contract | Verification |
| --- | --- | --- | --- |
| A0 | archived M0.4 | autonomous P1/E0, cap 256 | model-selected |
| A1 | complete initial permitted files, including public tests | P1/E0 normal actions, cap 512 | model-selected |
| A2 | same initial files | one literal EDIT patch or GIVE_UP, cap 512 | trusted automatic after valid change |
| A3 | same initial files | one complete replacement or GIVE_UP, cap 512 | trusted automatic after valid change |

All new conditions share TaskView, explicit single editable target, complete
initial readable-path text, bounded-Python language policy, inference settings and
resource limits. No hidden files, buggy-line annotations, solutions or extra hints
are added. A1 receives ordinary recent public observations thereafter. Source is
never truncated to fit preloading; excess context aborts. Every prompt and preload
has hashes. The first decision's task/file information is identical across A1-A3;
the action contracts/tool choices differ. All initial files are marked as initial
snapshots, not continuously refreshed contents.

A2/A3 use explicit versioned native JSON schemas. A2 permits only EDIT or GIVE_UP;
READ and VERIFY are absent from its wire schema and independently rejected by the
diagnostic Supervisor. A3 requires content or GIVE_UP, not tool choice; the target
path is fixed by the trusted harness. Parser maps only literal contract fields to
existing typed ActionRequests. No prose stripping, content repair, newline repair,
extra inference or intelligent conversion occurs. Original model output is saved.
GIVE_UP terminates normally and is distinct from malformed/infrastructure outcomes.
A1 legacy finish is recorded separately, not assumed to mean GIVE_UP/confidence.

`diagnostic.py` contains separate experimental adapters/controller. Shared Ollama
transport exposes prompt/format/parser hooks with unchanged defaults. The existing
Supervisor write/path/byte/policy/checkpoint methods are inherited unchanged;
every edit/replacement and verification passes through them. A3 uses the already
implemented bounded E1 path, not an unrestricted writer. ExperimentManager adds
only explicit diagnostic dispatch. Evaluators, logger, schemas, original prompt
builder, tasks, default Runner and Supervisor source are protected against changes.

A2/A3 consume one measured generation. Automatic public verification is logged as
a control-plane operation, not another LLM decision, and costs a real tool call and
verification attempt. A1 may use up to 15 decisions but one verification attempt.
No condition gets more attempts, reflections, memories or generated tools.

## Identity and Ceilings

Same four exact installed M0.4 digests, Ollama 0.35.1; no downloads. Live preparation
saves complete `/api/show` templates/system metadata/parameters/quantization.
Both Coder variants declare `general.finetune: Instruct` and expose chat templates;
this is metadata evidence, not an independent training-provenance audit. Friendly
names or chat templates alone do not establish instruction tuning. Qwen3's missing
finetune label is unknown, not proof it is a base model. Native `think=false` is
explicit for all, and unexpected thinking is an infrastructure interruption.

Source files are 53, 98, 104 and 158 bytes. Literal replacement JSON for unchanged
content is 90-199 bytes (~45-100 tokens at a rough 2 bytes/token); whole-file E0
patch JSON is 172-390 bytes including both strings. The common ceiling 512 provides
margin even at a conservative one byte/token for the original-sized patch. These
are estimates, not tokenizer counts or guarantees for arbitrary expanded code.
Actual output counts and backend `length` stop reasons are recorded. Limits never
change in response to comparative outcomes. A1 also gets 512, avoiding an A1/A2
cap mismatch; archived A0 retains 256 and is not rerun unnecessarily.

## Metrics and Interpretation

Definitions and five interpretation cases are preregistered. Count schema-valid
raw model choices separately from admitted/executed actions. Nonempty valid
modification means a changed candidate accepted by the Supervisor. Record syntax
validity separately from bounded-policy validity, unmatched/protected patches,
unchanged proposals, actual writes, candidate checkpoints and verification.
No candidate yields null syntax evidence, not a syntax failure. Test-executable
means changed candidate completed public pass/fail verification, not immunity to
runtime exceptions. Unittest assertion-failure/error counts are parsed only where
the completed public output permits; raw outputs remain available. Missing counts
are null, not estimated. Public task failures are retained individually.

The full primary matrix is 4 models x 3 conditions x 4 frozen tasks = 48 trials,
budget 1. Complete it even after an early public success; then stop. No automatic
1/3/5 scaling, model selection, Pi benchmark or M0.6. Optional A2b is deferred.
Public-only diagnostic interpretation is durably saved before private aggregation.
Hidden evaluation remains unchanged after normal Runner termination, including
baseline scoring when no candidate exists. It never supplies feedback or selects
conditions/models/protocol changes.

Competing explanations must remain visible: A1 preloading and cap differ from A0;
A2 removes multiple action choices and automates verification; A3 changes edit
primitive and removes patch matching. These do not isolate READ removal as the
sole causal factor. Family, quantization, templates and backend defaults covary.
One-shot, fixed-order results on exposed development tasks do not establish
intrinsic capability limits or hardware feasibility.

## Reproduction

Clean checkout, pinned installed models/runtime, fresh state paths:

```powershell
.\.venv\Scripts\python.exe scripts\validate.py
.\.venv\Scripts\python.exe scripts\smoke_m05.py --phase smoke --state .local/m05/SMOKE
.\.venv\Scripts\python.exe scripts\smoke_m05.py --phase comparison --smoke-receipt .local/m05/SMOKE/smoke-receipt.json --state .local/m05/COMPARISON
```

Smoke uses only calibration `smoke_area`, one call per model/condition, no applied
actions or benchmark scores. Completed smoke pins code/config/preparation/runtime
environment. No task-specific prompt tuning is allowed. A malformed smoke decision
is not automatically repaired; timeout/transport/thinking failures block comparisons.
Unit tests mock model responses and require no local models or downloads. Raw
requests, outputs, public candidates, public/private evaluations and prompt hashes
are in SQLite/content-addressed artifacts plus audited JSON/CSV research ZIP.
Research exports contain hidden evidence and must never be Runner input.
