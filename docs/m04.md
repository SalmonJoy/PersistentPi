# M0.4 Tiny Model Capability Ladder

## Freeze and question

M0.3 clean HEAD `d5956d2` passed all 117 tests and the original matrix/export
before annotated tag `m0.3` was created. No prior records are changed. M0.4 changes
model identity while holding P1 `runner-json-schema-1`, E0, shared messages/schema,
tools, context policy, Supervisor, Runner, verifiers and task versions fixed.
Protected component diffs against `m0.3` are checked by the run script. Added
observer code is research-only and never supplies feedback or interrupts loops.

Model order is fixed: llama3.2:1b control, qwen2.5-coder:0.5b, qwen3:0.6b,
qwen2.5-coder:1.5b, optional qwen3:1.7b. Optional inclusion is decided during model
preparation, before comparisons, under the preregistered disk/time limits. No
substitution, larger download, prompting optimization, Planner, memory, reflection,
E1 switch or Pi access. Quantization/template/tokenizer differences are observed
model-condition factors, not silently conflated with a pure size effect.

## Inference and thinking

Same temperature 0, seed 42, context 4096, cap 256, timeout 30s, keep_alive 5m;
all other M0.3 budgets remain fixed. Digests and runtime are pinned to the prepared
inventory and checked at reservation and before every generation. Model metadata,
stored size, parameter count, quantization, template/system hashes and backend
defaults are recorded. No backend template is replaced or forced across families.
HTTP messages are identical for matching initial task/budget states; their runtime
rendered templates and tokenization can differ. Every actual input token count and
prompt hash is retained.

Primary native request `think=false` is explicit for ALL models. `/api/show`
thinking defaults/values are saved; omitted metadata remains unknown, not inferred.
The installed runtime supports false/true for Qwen3 and reports default true.
See [Ollama thinking controls](https://docs.ollama.com/capabilities/thinking) and
[chat API](https://docs.ollama.com/api/chat). No `/no_think` suffix, prompt change,
hidden reasoning factor or repair is added. Nonempty thinking response is an
infrastructure interruption, never silently accepted or interpreted as an action.
Legacy M0.1-M0.3 requests without this explicit new policy remain unchanged.

Each model gets one first-decision adapter/template smoke call on `smoke_area`;
it neither edits nor evaluates a candidate and is not a benchmark score. A malformed
action is a model outcome, not automatic repair; backend/timeout/thinking failures
block comparison. The frozen smoke receipt pins code/config/inventory/environment.

## Tasks and passive metrics

Primary budget 1 tasks: `smoke_parse`, `smoke_sign`, `smoke_total`, `smoke_unique`,
with the exact M0.3 hashes. Older calibration tasks are adapter smoke only.
Preregistration `configs/m04-preregistered.json` was committed before comparisons.

Productive: successful first read of path/content/truncation evidence at a source
epoch, successful source change, or new public checkpoint/outcome evidence.
Duplicate reads/tests, rejected edits, malformed actions and finish are not
productive. This operational metric does not prove semantic usefulness. Epoch
increments only after a successful E0 edit; edits/undo still count as changes.
First read after a change is evidence at the new state, even if that particular
file was not modified. Verification can be productive without changing source.

Write requested: schema-valid edit_file. Authorized write attempt: reaches the
authorization stage, even if exact matching or bounded-Python applicability fails.
Write-attempt rate is fraction of tasks with >=1 authorized request; actual writes
are counted separately. No intended operation is guessed from malformed output.

Same-file reread: identical read evidence at unchanged source epoch. Identical
action repeats compare consecutive canonical requests; malformed decisions reset
adjacency. Consecutive non-state-changing decisions include productive reads/tests;
only source edits reset the streak. Unique-file counts are per task. Report reread
rates per decision and per successful read, source changes and maximum streak.

Full original response/parse/schema/authorized/applicable/executed/checkpoint/
verification/public/hidden funnel is retained, plus requested/authorized writes.
`decision_progress` events are explicitly `post_run_passive`; their source call IDs
link to actual Runner events. They cannot affect the task's actions, budgets or
feedback. No stagnation intervention is added.

## Viability, scaling and selection

V1: >=50% tasks attempt authorized modification. V2: >=50% reach public verification.
Both and zero interrupted runs are required. Eligible models alone get fresh
four-task budget 1/3/5 comparison, with no other factor changed. Models failing
gates get no additional attempt compute. Significant E0 applicability failures are
>=25% authorized edit requests and >=2 failures; this is evidence for later E0/E1
research only, not permission to change primitives.

Candidate selection uses primary budget-1 results only: public-pass count,
verification task rate, productive-action rate, smaller resident then stored bytes,
lower inference seconds, lower tokens. If any viable model has missing resident
metadata, stored size is the uniform footprint basis for all viable models. Exact
ties use stable model tag and are disclosed. Footprint is Ollama's immediate
post-primary API snapshot, not Pi RAM prediction or measured process RSS.
Selection never uses hidden scores. Durable public-only selection precedes private
aggregation. Scaling does not rerank the candidate. The leading viable model gets
three identical budget-1 replicates on smoke_parse; token/time/trace/result variance
is reported without a determinism guarantee.

Useful throughput uses final hidden task passes for researcher-only measurement,
with separate public throughput. Divide by summed per-trial end-to-end seconds,
not stopwatch time including downloads/tests/reports. Zero successes means null
tokens/solved and inference-seconds/solved, not zero or infinity. Solves/hour is 0
when wall time is known and success count zero. Unknown costs remain null. Include
load time and model preparation separately; fixed order/cache/thermal contention
limit latency comparisons. Four exposed tasks are not final-paper evidence.

## Reproduction and artifacts

Use a clean checkout and the pinned inventory, local installed models and runtime.
Models were prepared by `scripts/prepare_m04_models.py`; it records disk/models/
version before any pull and after each exact authorized tag. That command requires
a fresh output path and does not run inference. Do not overwrite old inventories.

```powershell
.\.venv\Scripts\python.exe scripts\validate.py
.\.venv\Scripts\python.exe scripts\smoke_m04.py --phase smoke --state .local/m04/SMOKE
.\.venv\Scripts\python.exe scripts\smoke_m04.py --phase comparison --smoke-receipt .local/m04/SMOKE/smoke-receipt.json --state .local/m04/COMPARISON
.\.venv\Scripts\python.exe scripts\persistentpi.py --state .local/m04/COMPARISON status
```

Fresh state paths only; no silent trial replay. The existing CLI STOP mechanism
remains. Tests mock Ollama and never need model downloads. SQLite schema stays
unchanged; versioned manifests/events carry model factors and passive metrics.
The database, artifacts, freezes, public selection, costs/summary, Markdown and
checksummed JSON/CSV research ZIP are in ignored `.local/m04/`; committed records
will identify exact paths. Full exports include private evaluator evidence and
must never be Runner input.

No Pi baseline remeasurement, cleanup or runtime benchmark is part of M0.4.
Candidate selection is provisional and makes no hardware feasibility assertion.
Stop after this milestone; no automatic Pi optimization or subsequent experiment.
